# 需求

- 检查并完善 `.gitignore`，避免提交缓存、测试产物、构建临时目录和生成的插件包。
- 检查 `.github/workflows/build-release.yml` 是否使用过时的运行时、Action 或发布流程，并按当前仓库实际情况修正。
- 审计当前工作区中的 Word 右对齐、Ruby、上标/字号、测试和中文 README 变更。
- 运行完整验证后创建清晰的 Git 提交。
- 将当前 `master` 推送到其上游 `origin/master`，并确认本地与远端同步。

# 验收标准

- 待提交内容不包含缓存、临时文件、生成包或敏感信息。
- 自动化测试、编译检查和 diff 检查通过。
- 产品改动和 CCG 归档均已提交。
- `git push` 成功，最终分支不再领先上游且工作区干净。
